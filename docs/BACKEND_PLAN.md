## STEP 1: Build the Ryu Flow Stats Poller (Weeks 1–2)

### What This Is

The Ryu controller is the brain of the entire system. It sits between Friend 1's switch (OVS) and everything else. Every **1.5 seconds**, it asks the switch: *"How much traffic has passed through each flow?"* The switch answers with a stats report. Your controller parses that report, computes per-flow metrics (PPS, BPS), and writes them to a CSV file.

**File to create:** `controller/simple_monitor.py`

---

### Line-by-Line Walkthrough of Key Sections

#### 1. Class Definition and OFP Version

```python
from ryu.base import app_manager
from ryu.controller import ofp_event
from ryu.controller.handler import CONFIG_DISPATCHER, MAIN_DISPATCHER, set_ev_cls
from ryu.ofproto import ofproto_v1_3
from ryu.lib import hub

class SimpleMonitor(app_manager.RyuApp):
    OFP_VERSIONS = [ofproto_v1_3.OFP_VERSION]
```

**Why `OFP_VERSION` 1.3?**
OpenFlow 1.3 is the industry standard for SDN controllers and is the version supported by modern Open vSwitch (OVS). It exposes full flow match fields (including `ipv4_src`, `ipv4_dst`), per-flow counters, and the ability to push drop rules — all of which you need. Version 1.0 does not expose IPv4 match fields properly. Always pin to 1.3.

---

#### 2. The `hub.spawn()` Call

```python
def __init__(self, *args, **kwargs):
    super(SimpleMonitor, self).__init__(*args, **kwargs)
    self.datapaths = {}
    self.flow_history = {}
    self.monitor_thread = hub.spawn(self._monitor)
```

**Why `hub.spawn()` and NOT Python's `threading.Thread`?**
Ryu is built on **eventlet**, a cooperative concurrency library. Eventlet is fundamentally incompatible with Python's native threading module — mixing the two causes deadlocks and unpredictable crashes. `hub.spawn()` is Ryu's eventlet-native way of starting a background greenlet (lightweight coroutine). Always use `hub.spawn()` inside a Ryu app. Never use `threading.Thread`.

---

#### 3. The `_monitor()` While-True Loop

```python
def _monitor(self):
    while True:
        for dp in list(self.datapaths.values()):
            self._request_stats(dp)
        hub.sleep(1.5)
```

This is the **polling engine**. Every 1.5 seconds it iterates over all connected switches and fires a stats request at each one. `hub.sleep(1.5)` is the eventlet-safe sleep — it yields control back to the event loop during the sleep period instead of blocking the entire process (which `time.sleep()` would do). The 1.5-second interval is a deliberate choice: fast enough to detect a DDoS spike quickly, slow enough not to overwhelm the controller with stats traffic.

---

#### 4. The `switch_features_handler` — Table-Miss Entry

```python
@set_ev_cls(ofp_event.EventOFPSwitchFeatures, CONFIG_DISPATCHER)
def switch_features_handler(self, ev):
    datapath = ev.msg.datapath
    ofproto = datapath.ofproto
    parser = datapath.ofproto_parser
    self.datapaths[datapath.id] = datapath

    # Install the table-miss flow entry
    match = parser.OFPMatch()
    actions = [parser.OFPActionOutput(ofproto.OFPP_CONTROLLER,
                                      ofproto.OFPCML_NO_BUFFER)]
    self.add_flow(datapath, 0, match, actions)
    self.logger.info("Switch connected: %s", datapath.id)
```

**What is the table-miss entry and why is it needed?**
By default, when a packet arrives at a switch and no flow rule matches it, the switch **drops it silently**. This is a problem — you need unrecognized traffic sent up to the controller for MAC learning and monitoring. The table-miss entry is a flow rule with **priority 0** (lowest possible) and an empty match (matches everything). Its action is `OFPP_CONTROLLER` — send the packet up to the controller. This ensures every new flow is visible to your monitoring code before it is handled by a more specific rule.

#### 5. The L2 Packet-In Handler — MAC Learning

```python
@set_ev_cls(ofp_event.EventOFPPacketIn, MAIN_DISPATCHER)
def packet_in_handler(self, ev):
    msg = ev.msg
    datapath = msg.datapath
    in_port = msg.match['in_port']
    pkt = packet.Packet(msg.data)
    eth = pkt.get_protocols(ethernet.ethernet)[0]

    dst = eth.dst
    src = eth.src
    dpid = datapath.id

    self.mac_to_port.setdefault(dpid, {})
    self.mac_to_port[dpid][src] = in_port  # Learn: src MAC came from in_port

    out_port = self.mac_to_port[dpid].get(dst, datapath.ofproto.OFPP_FLOOD)
    # ... install flow and forward
```

**Why MAC learning?** Without it, the switch would flood every packet out every port forever, creating broadcast storms and making your traffic measurements meaningless. MAC learning builds a `{mac → port}` table so the switch can forward intelligently. Once a flow is learned, Ryu installs a precise flow rule and the switch handles it locally — the controller only sees new flows via `packet_in`.

---

#### 6. The `_request_stats()` Call

```python
def _request_stats(self, datapath):
    parser = datapath.ofproto_parser
    req = parser.OFPFlowStatsRequest(datapath)
    datapath.send_msg(req)
```

`OFPFlowStatsRequest` is an OpenFlow message that asks the switch to report statistics for every active flow rule. The switch responds asynchronously with one or more `OFPFlowStatsReply` messages, which your `_flow_stats_reply_handler` processes. This is a request/reply cycle — you send the request, then wait for the reply event.

---

#### 7. The `_flow_stats_reply_handler` — The Most Important Method

This is the core of your data collection. Read every line carefully.

```python
@set_ev_cls(ofp_event.EventOFPFlowStatsReply, MAIN_DISPATCHER)
def _flow_stats_reply_handler(self, ev):
    body = ev.msg.body
    datapath_id = ev.msg.datapath.id
    now = time.time()

    rows = []
    for stat in sorted(body, key=lambda s: (s.match.get('ipv4_src', ''),
                                             s.match.get('ipv4_dst', ''))):
        # --- How to extract IPv4 src/dst from flow match fields ---
        match = stat.match
        if 'ipv4_src' not in match or 'ipv4_dst' not in match:
            continue  # Skip ARP, LLDP, and non-IP flows

        src_ip = match['ipv4_src']
        dst_ip = match['ipv4_dst']
        flow_key = (datapath_id, src_ip, dst_ip)

        new_packet_count = stat.packet_count
        new_byte_count   = stat.byte_count

        # --- How to compute PPS and BPS ---
        if flow_key in self.flow_history:
            prev = self.flow_history[flow_key]
            time_delta = now - prev['timestamp']

            if time_delta > 0:
                pps = (new_packet_count - prev['packet_count']) / time_delta
                bps = (new_byte_count   - prev['byte_count'])   / time_delta
            else:
                pps = 0
                bps = 0
        else:
            pps = 0
            bps = 0

        # --- Update self.flow_history ---
        self.flow_history[flow_key] = {
            'timestamp':    now,
            'packet_count': new_packet_count,
            'byte_count':   new_byte_count,
        }

        duration_sec = stat.duration_sec
        rows.append({
            'timestamp':    datetime.datetime.fromtimestamp(now).strftime('%H:%M:%S'),
            'src_ip':       src_ip,
            'dst_ip':       dst_ip,
            'pps':          round(pps, 4),
            'bps':          round(bps, 4),
            'packet_count': new_packet_count,
            'byte_count':   new_byte_count,
            'duration_sec': duration_sec,
        })

    # Append to CSV
    if rows:
        df = pd.DataFrame(rows)
        csv_path = 'controller/traffic_dataset.csv'
        header = not os.path.exists(csv_path)
        df.to_csv(csv_path, mode='a', header=header, index=False)
```

**Explanation of critical computations:**

| Concept | Explanation |
|---------|-------------|
| `ipv4_src` check | ARP and LLDP packets don't have IPv4 fields. Without this guard, your code crashes with `KeyError`. Always check before accessing. |
| `flow_key` | A tuple `(switch_id, src_ip, dst_ip)` uniquely identifies a flow across polling cycles. This is the key into `self.flow_history`. |
| `time_delta` | Time elapsed since last poll. This should be ~1.5s but may vary slightly. Dividing by `time_delta` gives the true per-second rate regardless of jitter. |
| PPS formula | `(new_packet_count - old_packet_count) / time_delta` — the delta between two successive polls gives you the rate over that window. |
| BPS formula | `(new_byte_count - old_byte_count) / time_delta` — same principle but for bytes. |
| `self.flow_history` | A dictionary that remembers the last-seen packet/byte count and timestamp for every flow. Without it you cannot compute deltas. It persists in memory for the lifetime of the controller process. |

## STEP 4: Train the ML Model (Week 6)

### What You're Training

A **RandomForestClassifier** — an ensemble of 100 decision trees that independently vote on whether a flow is normal or a DDoS attack. The majority vote is the final prediction.

### Why Random Forest (Not Deep Learning)?

| Criterion | Random Forest | Deep Learning (LSTM/CNN) |
|-----------|--------------|--------------------------|
| Inference speed | **< 5ms** ✅ | 50–200ms ❌ |
| Dataset size needed | 5,000 rows is fine ✅ | Needs 100,000+ rows ❌ |
| Explainability | Feature importances built-in ✅ | Black box ❌ |
| GPU required | No ✅ | Yes (ideally) ❌ |
| Risk of overfitting on small data | Low ✅ | High ❌ |

For a real-time DDoS detector with a small academic dataset, Random Forest is the correct choice. You can explain it to your examiner step by step.

**What precision, recall, and F1 mean in the attack context:**

| Metric | What it Measures | Failure Consequence |
|--------|-----------------|---------------------|
| **Recall** (DDoS class) | Of all real attacks, what % did the model catch? | **Low recall = attacks slip through undetected** — the worst outcome |
| **Precision** (DDoS class) | Of everything the model flagged as DDoS, what % was actually DDoS? | Low precision = blocking legitimate users — bad but recoverable |
| **F1-Score** | Harmonic mean of precision and recall | General model quality |

> [!IMPORTANT]
> **Recall is more important than precision** for a security system. Missing a real DDoS attack (low recall) is far more damaging than occasionally blocking a legitimate user (low precision). Optimize for recall first.

## STEP 5: Integrate ML into Ryu Controller (Week 9)

### What You're Doing

Loading `detector.joblib` into `simple_monitor.py` so the controller can automatically identify and block DDoS flows in real time — no human intervention needed.

---

### Where the Code Goes

The `model.predict()` call happens **inside `_flow_stats_reply_handler`**, immediately after computing `pps` and `bps` for each flow. This is the only place it makes sense — you have all the feature values available and you are already processing each flow individually.

Add the model loading in `__init__`:

```python
def __init__(self, *args, **kwargs):
    super(SimpleMonitor, self).__init__(*args, **kwargs)
    self.datapaths = {}
    self.flow_history = {}
    self.blocked_ips = set()

    # Load ML model if available
    model_path = 'ml_pipeline/detector.joblib'
    if os.path.exists(model_path):
        self.model = joblib.load(model_path)
        self.logger.info("ML model loaded: %s", model_path)
    else:
        self.model = None
        self.logger.warning("detector.joblib not found — using threshold fallback (pps > 10000)")

    self.monitor_thread = hub.spawn(self._monitor)
```

---

### The Auto-Block Flow

```
Flow stats received
       ↓
Compute pps, bps for each flow
       ↓
model.predict([[pps, bps, duration_sec, packet_count]])
       ↓
= 1 (DDoS)?
  ┌── YES ──────────────────────────────────────────────┐
  │  push_drop_rule(datapath, src_ip)                   │
  │  add src_ip to self.blocked_ips                     │
  │  write shared_state.json → status = "UNDER_ATTACK"  │
  └─────────────────────────────────────────────────────┘
  ┌── NO ───────────────────────────────────────────────┐
  │  Business as usual                                  │
  │  Log row to traffic_dataset.csv                     │
  │  write shared_state.json → status = "NORMAL"        │
  └─────────────────────────────────────────────────────┘
```

**Prediction code inside `_flow_stats_reply_handler`:**

```python
features = [[pps, bps, duration_sec, new_packet_count]]

if self.model is not None:
    prediction = self.model.predict(features)[0]
elif pps > 10000:
    prediction = 1  # Threshold fallback
else:
    prediction = 0

if prediction == 1 and src_ip not in self.blocked_ips:
    self.logger.warning("DDoS detected from %s — pushing drop rule", src_ip)
    self.push_drop_rule(datapath, src_ip)
    self.blocked_ips.add(src_ip)
```

**The `push_drop_rule` method:**

```python
def push_drop_rule(self, datapath, src_ip):
    """Install a high-priority drop rule for the attacking source IP."""
    ofproto = datapath.ofproto
    parser  = datapath.ofproto_parser

    match = parser.OFPMatch(eth_type=0x0800, ipv4_src=src_ip)
    # Empty actions list = DROP
    inst = [parser.OFPInstructionActions(ofproto.OFPIT_CLEAR_ACTIONS, [])]
    mod  = parser.OFPFlowMod(
        datapath=datapath,
        priority=100,           # Higher than normal forwarding rules
        match=match,
        instructions=inst
    )
    datapath.send_msg(mod)
```

---

### Fallback Threshold

> [!NOTE]
> If `detector.joblib` does not exist (because ML training hasn't happened yet), the controller falls back to: **`pps > 10,000` means DDoS**.
>
> This means the controller is **always functional**, even in Phase 1 before the ML model is trained. You can demonstrate basic detection in Week 2, then swap in the trained model in Week 9 with zero other changes.

## STEP 6: Flask REST API (Week 8)

### What You're Building

A simple, **read-only** REST API. It reads from `shared_state.json` and exposes that data to the React dashboard. It never writes to the controller, never modifies flow rules, and never touches Mininet. It is purely a data bridge.

---

### Architecture Note (CRITICAL — Read This Before Writing Any Code)

> [!CAUTION]
> **Ryu and Flask CANNOT run in the same Python process.**
>
> Ryu uses **eventlet** (async, cooperative multitasking). Flask uses **WSGI** (synchronous). When you try to start Flask inside a Ryu app, eventlet patches the socket library in ways that break WSGI, causing the API to deadlock or never respond.

**The solution is simple: run them as two separate processes in two separate terminals.**

```bash
# Terminal 1: Start the Ryu controller (writes shared_state.json)
ryu-manager controller/simple_monitor.py

# Terminal 2: Start the Flask API (reads shared_state.json)
cd backend_api && python app.py
```

**Communication between the two processes:**

```
┌─────────────────────────────┐        ┌──────────────────────────────┐
│   Ryu Controller (Proc 1)   │        │   Flask API (Proc 2)         │
│                             │        │                              │
│  _flow_stats_reply_handler  │        │  GET /api/network-stats      │
│         ↓                   │        │         ↓                    │
│  Writes shared_state.json ──┼──────→─┼─ Reads shared_state.json    │
│  (every ~1.5 seconds)       │  file  │  Returns JSON to React       │
└─────────────────────────────┘  system└──────────────────────────────┘
```

Ryu writes `shared_state.json` inside `_flow_stats_reply_handler`. Flask reads it on every API call. The `filelock` library ensures they never read/write simultaneously (race condition prevention).

### The `shared_state.json` Format

### File: `backend_api/app.py`

```python
from flask import Flask, jsonify
from flask_cors import CORS
import json
from filelock import FileLock

app = Flask(__name__)
CORS(app, origins=['http://localhost:5173'])  # Allow Vite dev server (React)

STATE_FILE = '../controller/shared_state.json'
LOCK_FILE  = STATE_FILE + '.lock'

def read_state():
    lock = FileLock(LOCK_FILE)
    with lock:
        with open(STATE_FILE, 'r') as f:
            return json.load(f)

@app.route('/api/network-stats', methods=['GET'])
def network_stats():
    """Returns current network status and traffic metrics."""
    state = read_state()
    return jsonify({
        'status':       state.get('status', 'UNKNOWN'),
        'timestamp':    state.get('timestamp'),
        'total_pps':    state.get('total_pps', 0),
        'total_bps':    state.get('total_bps', 0),
        'active_flows': state.get('active_flows', 0),
    })

@app.route('/api/blocked-ips', methods=['GET'])
def blocked_ips():
    """Returns list of IPs currently blocked by the controller."""
    state = read_state()
    return jsonify({
        'blocked_ips': state.get('blocked_ips', []),
        'count':       len(state.get('blocked_ips', [])),
    })

@app.route('/api/health', methods=['GET'])
def health():
    """Simple liveness check. No authentication required."""
    return jsonify({'status': 'ok', 'service': 'ddos-mitigation-api'})

if __name__ == '__main__':
    app.run(host='0.0.0.0', port=5000, debug=False)
```

**Endpoint documentation:**

| Endpoint | Method | Returns | Notes |
|----------|--------|---------|-------|
| `/api/network-stats` | GET | `status`, `total_pps`, `total_bps`, `active_flows` | Called by React dashboard |
| `/api/blocked-ips` | GET | `blocked_ips[]`, `count` | Shows attacker IPs |
| `/api/health` | GET | `{ "status": "ok" }` | No auth; used for monitoring |

## COMMON ERRORS & FIXES

> [!NOTE]
> These are the actual errors you will encounter. Bookmark this table.

| Error Message | Cause | Fix |
|---|---|---|
| `ryu-manager: command not found` | Ryu not installed or virtual environment not activated | Run `pip install ryu`, then `source ryu-env/bin/activate` |
| `ConnectionRefusedError: [Errno 111] Connection refused` | Flask API is not running | Open a new terminal and run `cd backend_api && python app.py` |
| `No module named ryu` | Python is running outside the virtual environment | Always run `source ryu-env/bin/activate` first |
| `KeyError: 'ipv4_src'` | Flow match has no IPv4 fields (ARP/LLDP packet) | Add `if 'ipv4_src' not in match: continue` at the top of the loop body |
| `FileNotFoundError: detector.joblib not found` | ML model not trained yet | This is expected in Phase 1. Controller uses threshold fallback (`pps > 10000`) — this is intentional |
| `ModuleNotFoundError: No module named 'filelock'` | Missing dependency | Run `pip install filelock` |
| `CORS error in browser console` | React origin not whitelisted in Flask | Ensure `CORS(app, origins=['http://localhost:5173'])` is in `app.py` and Flask was restarted after the change |
| `Switch not connecting to controller` | `topo.py` points to wrong controller IP | Ask Friend 1 to confirm they are using your actual IPv4 address (not `127.0.0.1`) in the `topo.py` controller config |
| `json.JSONDecodeError` in Flask | `shared_state.json` is being read while Ryu is mid-write | Ensure `filelock` is used on **both** the Ryu write and the Flask read |
| `hub.sleep is not defined` | Imported `time` instead of using `hub.sleep` | Replace `time.sleep(1.5)` with `hub.sleep(1.5)` inside Ryu |
